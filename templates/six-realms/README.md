# 默认基础模板：原图 → 彩色地块 → 动态领地

这三份是同一套输入与产物，不是三个随意挑选的相似版本。原始快照来自Git 372317d（初版分区实现addbfea）。底图和彩色图哈希已与用户刚确认的original-base.png/original-reference.png核对一致。尺寸941×1672，接近9:16；后续新生图默认明确要求9:16。

| 阶段 | 文件 | 形成过程 |
|---|---|---|
| 1 原始地形 | base.png | 先用生图确定大陆、海域、接壤关系和地表质感；用户反馈改图，确认地形 |
| 2 彩色地块 | reference.png | 以地形图为参考做彩色分区设计，安排不同面积的自然地块和边界；用户确认外观，先修接缝/异常直线 |
| 3 动态领地 | index.html + 数据 | 代码从确认的彩色设计提取区域ID、材质、边线、接壤关系；保持初始外观，再按实际归属逐像素染色 |

## 第三阶段如何形成

1. 用海水颜色和连通性区分海域与陆地。
2. 对陆地颜色聚类，以地块稳定内部作为标记，再用分水岭沿真实边缘扩展分区；不把纹理噪点当成小地块。
3. 将每个像素所属区域写进territories.u16（0为水域），导出130个区域的颜色、内部锚点、轮廓、邻接和接壤像素到territories.json。
4. 拆出material.png材质和borders.png/borders.u8边线；初始组合应与reference.png逐像素一致。底图与彩色设计间的美术变化以彩色设计为最终外观依据，不能只给底图粗略盖一层颜色。
5. 小兵沿区域内路径走到接壤处；达到接触门槛后累计20秒，由接壤处向目标内部洪泛推进并改变归属颜色；不跨海、不穿越第三块地。
6. 同一归属两侧的旧边线随推进消除；暂停冻结推进，恢复原貌应零像素差异。

## 模板和后续工作流的关系

三阶段各有独立的用户确认：满意采用、换图、局部微调、扩图。新版本保留历史。HTML工作台默认把生成图放入完整9:16原图框，并用可关闭的观众范围框模拟左右各10%裁剪。这个目录先保留最原始的动态演示，不把后续游戏框/英雄/城墙混入原始基础。

本模板用于地图图层与吞噬表现验证，不包含完整多人战争、战损、驻军、礼物结算或英雄绑定。后续接入游戏时，仅观众可见/青龙框内地块参与玩法，框外为装饰。

打开：启动工作流本地服务后访问/templates/six-realms/。页面提供原始底图、彩色目标对照、动态地图三个视图，以及播放20秒推进/暂停/恢复原貌。

## 默认取景与安全区

新生地图默认 9:16，等比例铺满，裁剪多余部分，不拉伸。扩图仅在构图内容不足时使用，不作为必经步骤。

原图框、左右各 10% 的观众范围框可分别开关；“上下安全区”同时开关顶部 5% 虚线和底部礼物区虚线。底部依据当前游戏测量：观众画布逻辑宽 393、高 873.333；礼物框 393×130，中心距底 52，屏内可见高度 117；连同上方说明条共 120.954（约 13.85% 高度）。这些辅助线不修改底图或区域数据。10% 是本项目设定，不代表平台所有场景的统一规则。

当前交互运行在统一工坊，行为由 ../../workshop/pipeline.mjs 固化提供。当前演示只有3个起点，自动逐块推进；不使用目录中历史 standalone/app.mjs 的固定排队逻辑。快速验收记录见 quick-acceptance.json，验收说明见 ../../workshop/ENGINE.md。
